# 客户端逆向：背包默认展平（Item 窗口宽窗模式）

> 姊妹文档：IDA 书签（前缀 `idaMCP: ITEMFULL:`）与本文件成对；改址或改述时两侧同步。
> 基线：`Angel.exe`（v83，IDA `D:\Downloads\Angel\Angel.i64`）；发布客户端为 `BeiDou.exe`（§6 逐字节核对）。
> 关联实现：`ezorsia/AddyLocations.h`（`dwInvExpanded*` / `dwSaveCharacter` / `OFF_CConfig_GameOptKey`）、
> `ezorsia/ItemWndExpanded.cpp`、`config.ini` 的 `itemWndExpanded` / `itemWndRemember`。
>
> **地址族群提醒**：本次逆向在 `Angel.exe` 上完成；`BeiDou.exe` 已按 §6 逐字节核对。换客户端前必须重新核对。

## 0. 一句话

背包（Item 窗口）的"展平"就是客户端自带的**宽窗模式**（`UI/UIWindow.img/Item/fullbackgrnd`，5 个分页并排、
583 宽、不建滚动条），整套布局由**一个字段** `CUIItem+604h` 决定。该字段在构造时由
`CConfig::GetInventoryExpanded` 读注册表得来，而玩家用按钮写下的那个注册表值**活不过一次正常退出**
（`CConfig::SaveCharacter` 会把整个 GameOption 键擦掉再写回它自己那份选项表），所以每次开客户端都落到
硬编码缺省值 0（窄窗+滚动条）。本插件只做两件事：把缺省值改成 1，以及让玩家的选择真的留住。

## 1. 机制：一个字段决定整套布局

- `CUIItem+604h`：0 = 窄窗（155 宽、单分页、建滚动条），1 = 宽窗（583 宽、全分页、无滚动条）。
- 写它的只有两处：
  - `CUIItem::CUIItem`（构造）从 `CConfig::GetInventoryExpanded` 取初值；
  - 展平/收起按钮的处理函数 `sub_81E541` 取反后回写，并顺带写注册表。
- 读它的地方：`OnCreate`（选背景 `Item/backgrnd` ↔ `Item/fullbackgrnd`、是否建 `CCtrlScrollBar`、
  按钮 id 2005 展平 / 2006 收起）、`Draw`、`GetItemSlotRect`、`GetSlotPositionFromPoint`、`OnTabChanged`。
  所以**改构造时读到的值 = 改整套布局**，不需要动任何绘制或坐标代码。
- 窗口实例的生命周期：`CWvsContext::UI_Open` 只在 `[ctx+3438]` 为空时 new 一个 `CUIItem`，
  即**一个会话只构造一次**。这解释了两个现象：会话内点过按钮就一直有效；重开客户端才回到缺省值。

## 3. 为什么"点一次"不能永久展平

`CConfig::SaveCharacter` 的保存法是 **枚举 → 全删 → 只写回自己那份表**：

```
0049D9DA  call RegEnumValueA      ; 枚举 GameOption 键的全部值名，收进一个 ZArray<ZXString>
0049DA62  push [ecx+eax*4]        ; 值名
0049DA65  push [esi+0C8h]         ; GameOption 键
0049DA6B  call RegDeleteValueA    ; 逐个删除
0049DA8E+ ...                     ; 再写回 uiWndX/Y/Opt(键0) 与 goWhisper/goQuickType/QuestAlarm_*/
                                  ; DialogVisible/LastConnectedVersion(键2)
```

- `RegEnumValueA` / `RegDeleteValueA` 在整个客户端里**各只有这一处调用**（xref 各 1），所以这就是唯一元凶。
- 写回表里**没有 `InventoryExpanded`**，于是按钮刚写下的值在这一步被删掉。
- 调用方：`CWvsContext::OnLeaveGame`（退出）、`CUIGameOpt::SetRet`（游戏选项对话框点确定）、
  `CUIStatusBar::OnCreate`、`CConfig::~CConfig` —— 退出和改设置都会擦。

**注册表实测（本机，玩家确实点过那个按钮）**：

```
HKCU\Software\Wizet\MapleStory\g0_0_00000001
    goWhisper=1  goFriend=1 ... QuestAlarm_opened=1  LastConnectedVersion=0x53 ...
    （无 InventoryExpanded）
```
`g{世界}_{?}_{角色ID:08X}` 就是 GameOption 键；`QuestAlarm_opened` 在（它是写回表成员），
`InventoryExpanded` 不在 —— 与 §3 的代码结论一致：**写是写进去了，退出时被擦掉**。

## 4. 补丁

只改两处，都是"复用客户端自己的通路"，不新增行为：

**(a) 缺省值 → 展平**（`config.ini` 的 `itemWndExpanded`，默认开）

```
0049F603  6A 00   push 0     ->   6A 01   push 1     ; GetOpt_BOOL 的第 4 个参数
0049F605  50      push eax   ; "InventoryExpanded"
0049F606  6A 02   push 2     ; GameOption 键
0049F60A  E8 ...  call CConfig::GetOpt_BOOL
```
只改 `0x0049F604` 这一个字节（`00` → `01`）。**注册表里真存着值时仍以存着的为准**，所以它只决定
"没表过态的角色"。

**(b) 让按钮的选择活过退出**（`config.ini` 的 `itemWndRemember`，默认开）

不碰 §3 那个删除循环，而是挂钩 `CConfig::SaveCharacter`（`0x0049D90D`）：

```
进入 hook：  key = [CConfig+0xC8]；key == 0 就直接放行（与客户端自己的门控一致）
             读 n = CConfig::GetInventoryExpanded(CConfig)      ; 此刻键里还有值
             放行原 SaveCharacter                              ; 客户端照旧擦 + 写回自己的表
             写 CConfig::SetInventoryExpanded(CConfig, n)      ; 把这一个值放回去
```

- 入参/时序：`SaveCharacter` 是 `__thiscall`，`this` = `CConfig`；hook 用 `__fastcall` 包装
  （`this` 进 ECX，EDX 不用），与原函数无栈参时的清理方式一致。
- 为什么不用"跳过删除"的 code cave：值本身已经在键里，读一下再写回就够，且**不必写裸汇编**。
- 组合语义：`itemWndExpanded` 管"没表过态"，`itemWndRemember` 管"表过态之后按玩家的来"。
  两个都开 = 客户端行为回到它自己的设计意图 + 新角色默认展平。

- **两 exe 逐字节一致**（`Angel.exe` 对 `BeiDou.exe`，`DYNAMIC_BASE` 未置位 ⇒ 无 ASLR，地址即绝对值）：

  |---|---|
  | `0x0049F5DA` | `B8 60 1C A8 00 E8 B4 15 5C 00 51 56 8D 45 F0 68 97 11 00 00 50 8B F1 E8` |
  | `0x0049F62C` | `B8 74 1C A8 00 E8 62 15 5C 00 51 56 8D 45 F0 68 97 11 00 00 50 8B F1 E8 BD F1 2F 00` |
  | `0x0049F603` | `6A 00 50 6A 02 8B CE E8 CC F7 FF FF` |
  | `0x0049D90D` | `B8 64 19 A8 00 E8 81 32 5C 00 81 EC 28 01 00 00 56 8B F1 83 BE C8 00 00 00 00` |
  | `0x0049DA62` | `FF 34 81 FF B6 C8 00 00 00 FF 15 B8 05 BF 00` |

- **构建期自检**（`ItemWndExpanded.cpp`）：两处补丁都在动手前核对过站点形态与调用目标
  （`push 0` 的 opcode/立即数、`call CConfig::GetOpt_BOOL` 的 rel32、`push 1197h` 的 StringPool id、
  `SaveCharacter` 里的 `cmp [esi+0C8h]`），不符即跳过并打印，绝不盲改。
- **产物静态核对**（`out/Release/ijl15.dll`，本次构建）：
  `6A 01 68 04 F6 49 00 E8 ... 83 C4 08 80 3D 04 F6 49 00 01` ⇒ `Memory::WriteByte(0x49F604, 1)`
  紧跟一次回读校验；`push 0D D9 49 00` 在位（detour 目标）；五条日志串齐全。
- **未验（需要实机）**：`BeiDou.exe` 清单是 `requireAdministrator`，构建机上的自动启动被拒，
  运行时内存验证与"开一次背包"的目视验证**都还没做**。实机验收清单见 §7。

## 7. 风险与未验证点

1. **实机未验**（见 §6）。建议的 A/B：
   - 直接开客户端进角色 → 打开背包应是展平（宽窗、无滚动条）；点一次收起 → 关背包再开，仍是收起
     （会话内实例只有一份）。
   - 正常退出客户端 → 重进 → 仍应是**收起**（这是 `itemWndRemember` 的效果）。
   - 把客户端 `config.ini` 的 `itemWndRemember` 置 `false` 再来一遍：重进应回到**展平**（值被擦掉，
     落到缺省值）。
   - 注册表旁证：一次正常退出后 `...\g0_0_<角色ID>\InventoryExpanded` 应存在且等于玩家最后的选择。
2. **崩溃退出不走 `SaveCharacter`**：这时注册表里留着上次写的值，下次开客户端就按它来
   （= 玩家最后的选择）。若希望"任何情况下都展平"，应改用"恒定返回 1"的做法而不是本模块的缺省值补丁。
3. **`CConfig::~CConfig` 路径**：那时键句柄可能已关闭；hook 用 `key == 0` 直接放行，
   不会在关闭流程里多调 `StringPool`/注册表。
4. **超过 96 格**：展平窗的扫描上界写死 97（见 §5）。服务端若发放超过 96 格，展平模式下够不到多出的格子。
5. **编译告警**：本机 ANSI 代码页是 950，含中文注释的源文件会有 `C4819`
   （`Client.cpp` 等既有文件同样如此）；本模块注释为纯 ASCII，只有引用中文文档名的那几行例外。
6. 换客户端（非 `BeiDou.exe`）前必须重做 §6 的逐字节核对；自检不通过时插件只打印跳过，不会改坏。

## 8. 配置键（`config.ini` 的 `[optional]`）

| 键 | 默认 | 作用 |
|---|---|---|
| `itemWndExpanded` | `true` | 把 `CConfig::GetOpt_BOOL` 的缺省值从 0 改成 1：没表过态的角色，背包一打开就是展平。置 `false` = 原版默认（窄窗+滚动条） |
| `itemWndRemember` | `true` | 挂钩 `CConfig::SaveCharacter`，让按钮的选择活过退出。置 `false` = 原版行为（值在退出时被擦掉，玩家的切换只在本次会话内有效） |
